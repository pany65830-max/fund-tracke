# 基金信息追踪网页应用 — 设计文档

**日期：** 2026-08-04  
**状态：** 待用户审阅  
**定位：** 团队内部日报站（有链接即可访问，无登录）  
**部署：** 免费方案 — GitHub Actions 定时更新 + Cloudflare Pages / GitHub Pages 托管  

---

## 1. 目标与约束

| 项 | 约定 |
|---|---|
| 目标 | 团队每日查看四家基金公司资讯 + 四家旗下 ETF 数据，替代群转发 |
| 受众 | 内部团队；无对外宣传要求 |
| 访问 | 公开 HTTPS 链接，无登录；首版不做邮件/企微推送 |
| 更新 | 每个交易日 08:30（北京时间）全自动跑一轮 |
| 历史 | 可按交易日回看，保留约 90 个交易日 |
| 风格 | 大方简洁金融风（浅灰底、白卡片、红涨绿跌）；非红色火箭强还原 |
| 预算 | 首版零服务器成本（免费托管 + Actions） |

**明确不做（首版）**

- 登录 / 权限体系  
- 邮件日报、群机器人推送（二期可选）  
- 微信公众号全文镜像  
- 红色火箭式复杂可视化（聚焦板块 / 风向标 / 主力追踪 / 市场温度）  
- 全市场 ETF（仅四家公司产品）

---

## 2. 信息架构

### 2.1 全局

- 顶栏导航：**基金资讯** | **ETF 看板** | **日期选择器**（默认最近交易日）
- 状态提示：「数据日期 · 今日已更新」或「部分更新失败 / 展示上次成功数据」

### 2.2 页面一：基金资讯

**筛选（可组合）**

1. **机构**：华夏 / 易方达 / 国泰 / 华泰柏瑞 / 上交所 / 深交所 / 全部  
2. **类型**：研报 / 新产品发行 / 主动 ETF 公告 / 一般信披 / 交易所资讯 / 其他  

**列表字段：** 标题、机构标签、类型标签、来源（iFind / 微信 / 官网）、发布时间、摘要  

**详情页：**

- iFind 能拿到正文 → 自建页展示全文 + 来源外链  
- 微信等无法稳定取全文 → 摘要 +「阅读原文」外链  
- 不去镜像微信全文（合规与稳定性）

### 2.3 页面二：ETF 看板（仅四家公司 ETF）

自上而下模块：

| 模块 | 内容 |
|---|---|
| A. 行情概览 | 与旗下 ETF 相关的指数点位 / 涨跌小卡 |
| B. 板块/主题表现 | 相关行业/主题涨跌网格 |
| E. 热榜 | 净流入、涨幅、成交额等列表（范围限四家产品） |
| F. 产品列表 | 按公司分组：代码、名称、涨跌、份额/规模等基础字段 |

同一日期选择器，展示该日快照。

### 2.4 响应式

- 桌面：清晰导航 + 卡片/表格网格  
- 移动：单列卡片，为后续手机使用打好基础（首版不单独做 App）

## 3. 数据源与流水线

### 3.1 资讯源

| 源 | 覆盖 | 入库内容 |
|---|---|---|
| iFind API（主源，有调用限额） | 四家公司相关资讯 | 标题、摘要、正文（若有）、时间、原始分类等 |
| 微信公众号（补源） | 四家官方主号 + 上交所 + 深交所公众号 | 标题、摘要、封面、原文链接（不存全文） |
| 交易所官网 | 上交所、深交所官网资讯/公告 | 标题、摘要/正文（以页面可稳定解析为准）、原文链接 |

### 3.2 处理规则

1. **调度：** 交易日 08:30 一批处理；非交易日跳过  
2. **去重：** 同机构 + 近似标题 + 近似时间合并；优先保留带 iFind 正文的版本  
3. **自动分类：**  
   - 机构：来源账号/接口字段映射  
   - 类型：iFind 字段 + 标题/正文关键词规则；无法识别 →「其他」  
4. **配额：** iFind 调用集中在早间批处理；白天站点只读已生成数据，避免重复耗配额  
5. **容错：** 子任务失败时保留上次成功快照，页面展示告警状态；Actions 日志可查  

### 3.3 ETF 数据

- 维护可配置的 **四家公司 ETF 产品白名单**  
- 每交易日写入快照：指数概览、主题/板块表现、热榜指标、产品行情字段  
- 滚动保留约 90 个交易日；更早数据可删除  

### 3.4 配置项（便于团队增删）

- 产品白名单  
- 公众号列表、官网入口列表  
- 类型打标关键词规则  
- 交易日日历来源（或简易节假日表）

## 4. 技术架构（免费方案）

```text
[开发者电脑]  编写静态前端 + 拉取脚本
       │
       ▼
[GitHub 仓库]
  ├── web / 前端（推荐 Vite + React，静态导出）
  ├── scripts / 日更流水线（iFind + 微信 + 官网）
  ├── data / 日快照 JSON（首版默认；必要时再接免费 DB）
  └── .github/workflows / 交易日 08:30（Asia/Shanghai）定时任务
       │
       ├─► GitHub Actions：拉数 → 打标 → 写 data → 提交或产物
       └─► Cloudflare Pages（优先；国内访问更稳）/ 备选 GitHub Pages
```

**密钥：** iFind 等凭证只放 GitHub Secrets，不进仓库。  

**数据存储首版建议：** 仓库内按日 JSON（实现简单、零费用）；若体积或并发成问题，再迁免费 Turso / Supabase。  

**微信拉取实现：** 设计层只要求「摘要 + 原文链接」；具体技术（官方接口、RSS、可维护的抓取方案等）在实现计划中按可用性选定，失败时该源降级、不影响 iFind/官网。  

**交易日判断：** 使用可配置的节假日/休市表（或可信日历数据源），避免周末误跑浪费配额。  

**团队用法：** 书签固定链接；每天 8:30 后打开，看顶栏数据日期即可。

## 5. 错误处理与可观测性

- Actions 失败：通知仓库 Actions 状态（首版可不做额外推送）；站点显示「未更新/部分失败」  
- 单源失败不影响其他源已成功写入的数据  
- 关键字段缺失时列表仍可展示，详情降级为摘要 + 外链  

---

## 6. 二期可选（不在首版范围）

- 邮件 / 企微机器人摘要推送  
- 简单密码门禁或 IP 限制  
- 红色火箭风格可视化卡片  
- 人工校正分类的轻量后台  
- 迁国内云主机（若免费链路不稳定）

---

## 7. 成功标准（首版验收）

1. 团队用一个 HTTPS 链接打开，桌面与手机浏览器均可阅读  
2. 交易日自动更新资讯（含机构+类型标签）与四家 ETF 看板数据  
3. 可切换查看近约 90 个交易日内的历史日  
4. 资讯可进详情；有原文链接；iFind 有正文时页内可读  
5. 零付费云主机；密钥不泄露进公开代码
